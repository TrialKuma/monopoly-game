# 五城建筑重建：上一版历史记录

本目录记录“140 件按图重建 + 5 件 Pixal3D 住宅”的旧方案。用户要求全部建筑采用真正的三视图 AI 建模，后续全量替换的输入、原生推理、逐件验收和发布流程见 [全量三视图 AI 建筑替换](../full-ai-city/README.md)。下面的交付数量、预算和测试结果均属于旧版，不代表本轮已完成。

旧建模脚本仅向 `legacy-builds/` 导出历史对照资源，已禁止覆盖游戏正式建筑集。

在本地预览服务器打开 `/art-review.html`，可以旋转游戏实际使用的建筑，同时查看该地区的生成三视图。页面逐件标明 Pixal3D 多视图模型或 Blender 三视图重建模型。

## 三视图到游戏

1. `references/` 保存每个地区的基础建筑、公共建筑、大地块建筑三组生成三视图，共 15 张设计板及提示词。每一组包含正面、右侧、背面。
2. 同目录另存各地区小住宅的三个独立透明视图，用于本机 Pixal3D 原生多视图输入。发现背面重复、烟囱方向错误、构图尺度不一致时重新生图；修正提示词也归档。
3. Pixal3D 工具、输入来源、模型处理与验收记录放在 `../themed-city-kit/`。多视图使用假定相机方位，参考图没有精确相机标定；不把它描述为精密摄影测量。
4. `../build_regional_city.py` 按这些设计重建完整的升级家族，并把通过检查的 Pixal3D 小住宅接入对应二级住宅。导出的正式模型位于 `../../assets/models/regions/`。每个地区 29 个命名资产，五图共 145 件；资产清单逐件记录来源和模型指纹。
5. 检查正、侧、背、左四面，处理缺面、轴向、地面高度和贴图；再验证真实模型的三个等级均不会遮挡落点和产权框。原生生成成功本身不等于验收成功。

旧版交付为 **140 件按图重建 + 5 件真实 Pixal3D 住宅**。`legacy-runtime-release.json` 冻结旧版正式资产及来源；`../themed-city-kit/reports/approved-houses.json` 记录五件住宅实际推理、贴图与修补情况。法式、京都及港湾模型做了局部缺面修复；保留少量神经生成的边缘不规则。港湾模型生成了两根烟囱，这是与单烟囱参考图的明确差异。

## 预算与实际限制

普通重建模型控制在 23,000 三角面内，大型地块在 35,000 内。神经生成的住宅为约 180,000 面、2048 像素贴图，是明确记录的预算例外；只在对应二级住宅使用，按地图加载，棋盘实例共享几何与材质。外围使用同地区轻量建筑。减到 90,000–120,000 面曾损坏细部，因此没有采用该版本。

三视图约束外形、比例和地区构件，重建模型不是参考图的逐像素复制。生成网格与按图重建明确分开记录，不能将全部 145 件声称为神经模型生成。

## 验证入口

- `node tests/check-regional-kit.mjs`：145 件模型、尺寸、等级增长、构件、三角面数及 AI 来源/贴图指纹。
- `node tests/check-landing-clearance.mjs`：全部地图的一级、二级、三级模型与棋子落点。
- `node tests/check-ownership-frames.mjs`：产权框、公共边框、地区模型选择。
- `node tests/check-model-loading.mjs`：异步载入与地区优先选择。
- `node tests/check-model-cache.mjs`：棋盘与外围只解码一次、重试及位图释放。
- `node tests/check-regional-scenery-budget.mjs`：真实加载后的五图外围预算，避免高面数住宅被展开复制。
- `node tests/check-city-weather.mjs` / `node tests/check-roof-snow.mjs`：材质季节变化及积雪分类。

CPU 测试加载真实网格、UV 和材质绑定，但不解码纹理像素。材质与画面另用浏览器检查。手机宽度预览用于操作和可读性检查，不能替代真实手机 GPU 性能测试。

2026-10-23 最终验证通过：145 件实际资产；五图三级共 342 落点 / 9,234 次网格净空检查；65 个地产框、36 个公共框及 145 个地区优先路由；五图真实外围预算；19 项季节测试、17 项积雪测试、7 项缓存生命周期及 8 项加载时序。仓库/门票/结算等原有游戏规则回归通过。`qa/` 保存同一浏览器连续切换五图的实际游戏截图，以及 390×844 手机宽度的建筑近看和设计对照页截图。
