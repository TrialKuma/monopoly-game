# 全量三视图 AI 建筑替换

当前目录是 2026-10-23 启动的全量重做工作区。**生成队列、候选模型、已审核模型、正式游戏资产分别记录；排队或生成成功不代表已经交付。**

2026-10-24 已完成交付集成：147 件近景和 25 件远景均已逐件批准，生产控制器已自然结束。五图成组画面与手机视口游戏验收均已记录通过，精确证据已校验；12 个正式模型包及 145 个模型对应预览已全量发布。五项正式资源检查与正式入口的港湾竖屏加载、升级和确认事件烟测通过。发布记录以 `../regions/runtime-release.json` 为准，实际检查、限制与 Git 状态见 [交付记录](reports/runtime-integration-preparation-20261024.json)。

## 范围

- 五张地图各 29 个可玩建筑资产，共 145 个。住宅、商铺、旅馆、公馆、大酒店、商会、温泉庄园的三个等级分别生成；公共建筑每图八个。
- 地中海灯塔、阿尔卑斯风车两个外围主建筑也改用三视图生成。
- 四套原有住宅的独立三视图输入经过复核继续使用；港湾住宅已重做为同一张三联图。原有推理结果也必须重新经过本轮五面检查，不能因来源真实自动通过。
- 外围重复建筑使用同地区 AI 建筑的派生模型。景观植物、铺装、石头及家具不计作建筑生成资产。

## 制作与验收约束

1. 为每栋建筑生成同一物体的正、右、背三视图，保持一致比例、材质、屋顶及门窗位置。每个等级有自己的设计，不以缩放同一神经网格冒充升级。
2. 原始生图和完整提示词保存在 `references/<map>/`。透明三联图仅在模型输入准备阶段按透明间隙分离，记录裁切矩形和母图哈希；不重绘建筑或把程序化几何作为神经输出。
3. 使用本机 Pixal3D 的 `pipeline_mv.json` 与 `run_mv`，每件记录三张输入、模型配置、实际推理输出和后处理来源。相机方位是假定参数，不是照片标定结果。
4. 手机用简化网格必须来自实际神经高模；贴图与轮廓要经过近景核对。不能为了面数或文件体积换回积木模型。
5. 单栋正、右、背、左、等距五面及原始模型对照检查通过后，才写入 `approved-assets.json`。它只批准精确哈希对应的单体版本；排队、推理完成和脚本导出都不能自动批准。总览图同时绑定模型哈希和七张实际渲染图片的哈希，后续返修必须重新组合总览与审核。
6. `tools/pack_runtime.py` 只打包和统一缩放已审核来源，原样复制网格、UV、材质和贴图二进制；缺失任意建筑直接失败。单图候选用于制作检查。五张地图全部经过成组与实际竖屏画面检查，记录到 `regional-review.json` 后，才允许一次性发布147件。
7. 全量接入后重新检查实际落点、边框、动态部件、资源释放、竖屏画面及五图的风格区别。

## 后处理与远景

原始神经输出保持不变。降面、重新展开 UV、贴图烘焙与局部网格修瑕都在派生副本上进行。局部修瑕允许根据相邻完整墙面约束回正内陷顶点、补小范围墙洞及重新三角化；必须记录处理范围、移动顶点或新增面的数量，并检查修整前后图像。不能用手工重建主体替代 AI 建筑。

新推理会同时保留该次运行的原始神经属性场。手机几何可由同一原始模型简化后，恢复到原场坐标，用原生工具重新展开 UV 并直接采样该场生成材质；这一阶段不重新推理，也不再改变几何。对没有保留原场的早期模型，可只用原生 UV 展开，再从原模型的实际贴图转移颜色。两条路径分别记录来源，不能把后者写成神经场重采样。原始大模型和属性场属于本地重现档案，正式模型、输入三视图、处理记录及审核图片保存在版本库。

若原始模型本身缺面，重贴图不能算修复。先重新生成或完成有明确边界和数量记录的局部修瑕，再独立检查最终手机模型。修补、UV 调整和材质转移各自记录实际执行的工具版本，不能把新增补面冒充原始推理中的面。

近景普通建筑目标约三万三角面，大地块建筑与动态主景目标约四万五千面。普通建筑超过三万二千面时，需要记录保留何种可见轮廓与结构的具体原因。最终判断以手机尺度下的实际完整性为准，不以面数单项判断质量。

个别普通建筑在四万五千面仍会损坏薄墙或窗框时，可在五面实看通过后单独批准最高六万五千面，并记录具体原因。该例外不改变其他建筑默认预算，也不能绕过整图的面数、绘制次数和显存检查。处理报告同时保留请求面数与实际面数，避免将未达到的目标写成完成值。

外围复用每图住宅三级、商铺二级、旅馆二级、公馆二级和路口驿站，共二十五个派生远景模型。它们来源于同件已批准近景模型，目标约一万二千三角面，使用较小贴图并单独进行五面检查。远景派生不计入一百四十七次原生生成数量。为避免二次法线烘焙产生黑墙，远景保留几何法线与颜色、粗糙度贴图，不使用二次切线空间法线贴图。

个别远景建筑若在默认面数下损坏屋檐或窗框，可在实际检查后单独保留到两万面，并记录理由；整片外围仍需满足原有二十万面预算，不能因单体例外统一提高场景预算。

## 查看实际结果

- `art-review.html`：逐件旋转模型，并与该件实际推理使用的正、右、背输入对照；候选模型的输入依据对应处理报告定位，不依据可能已改版的生成队列。
- `art-board.html`：整张地图二十九件建筑同屏对照，同一家族使用一致镜头尺度，以检查等级递进与地区风格。
- `art/full-ai-city/portrait-review.html`：在独立的 390 × 844、360 × 740 或 430 × 932 网页视口中运行完整游戏，检查实际竖屏布局。

未发布整图候选通过 `artStage=candidate` 参数查看。只有全部单件、远景及五图整体检查完成，才替换游戏的正式资源。

`tests/check-ai-board-budget.mjs` 检查实际安装的整套建筑资源、三种等级占满棋盘时的三角面及建筑绘制数量，并估算未压缩纹理占用；`tests/check-regional-scenery-budget.mjs` 检查外围实例。它们属于资源检查，不等同于手机真机帧率测量。全量发布后仍以实际竖屏画面的清晰度和操作表现复核结果。

## 地区风格

| 地区 | 统一建筑语言 |
| --- | --- |
| classic | 法式奶油石墙、蓝灰折线屋顶、绿色门窗、铁艺与老虎窗 |
| compact | 京都町屋、深木格栅、米色灰泥、蓝灰瓦屋檐、纸灯笼 |

同地图统一圆润程度、明暗、材质尺度和细节密度。地区差异由建筑轮廓、屋顶构造、立面和功能构件体现，不能只换颜色。
