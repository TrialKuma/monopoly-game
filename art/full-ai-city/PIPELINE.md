# Native three-view generation and mobile derivative pipeline

This queue covers 145 distinct playable buildings plus two central landmarks. Each source must be a completed local `Pixal3DMVImageTo3DPipeline.run_mv` inference using three independent RGBA images. Four villa-level-2 input sets retain their earlier independent references; Harbor villa-level-2 now uses a new reviewed triptych. Reused inputs do not automatically approve an old mesh. Source defects are diagnosed before a retry: an improved reference or new neural attempt preserves its predecessor, while a bounded local neural-surface repair may be used with explicit geometry/UV provenance. Authored replacement buildings are prohibited.

## Reference input

The reference team supplies a transparent horizontal front/right/back design triptych and matching `.generation.json`. Only explicitly reviewed statuses are eligible, and the metadata SHA must match the PNG. Preparation finds transparent vertical gaps, crops complete views, and adds shared square transparent padding with a common vertical origin. It does not rescale, recolor, paint, mask or synthesize any pixels. Crop boxes, padding, decoded pixel hashes, full source hashes and individual image hashes are recorded. Immutable input copies live under a source-hash directory. The camera poses are assumed 0/90/180 degree orbit views at 20 degree horizontal FOV, taken from the official example; these are not measured camera calibration.

## Native inference and hardware

The actual local Pixal3D pipeline supports `1024_cascade` and `1536_cascade`. Its separate 512 shape stage is part of the 1024 cascade; it is not an available standalone 512 Pixal generation mode. The queue therefore retains the verified native 1024 cascade, original multi-view checkpoints, average fusion, 12/12/12 sampling steps, native parameter dtype, low-VRAM mode and 4096 source texture export. No silent 512 quality downgrade is used.

Each process acquires the existing shared GPU lock. The proven streaming loader and single-use retirement adapters are reused without changing shared upstream files or weights. Models are not retained across jobs because that would conflict with the verified single-use lifetime. A measured earlier house load took 19.437 seconds out of 222 seconds total; the first new shop completed in 201.7 seconds. Each job records its actual timings, stages, peak allocation and exact executed source snapshot.

On the local 5070 Ti, observed CUDA peaks around 16.365 GiB exceed the approximately 15.9 GiB dedicated allocation. Successful runs therefore rely on Windows shared GPU memory spill; this is not claimed to fit solely within dedicated VRAM. The owned near, repaired-source and hybrid CPU controllers share one operating-system file lease, so only one CPU Blender child runs at a time. The lease also waits for an already-running manual Blender process. Source reconstruction requires at least 9 GiB available RAM, coordinate preparation 8 GiB, and small finalization/far work 4.5 GiB. These are launch guards, not a claim that RAM stays constant during inference. A worker that cannot meet its own memory guard waits without holding the CPU lease; after acquiring the lease it rechecks both memory and existing Blender processes and releases immediately if admission has changed. This lets eligible 4.5 GiB finalization or pose review proceed while a 9 GiB reconstruction waits, without lowering either threshold. Per-process wait reasons and current owner metadata are advisory audit files; the operating-system byte lock remains authoritative. Classic near derivatives, then its needed far derivatives, lead the CPU queue so one whole map can be reviewed early. No user applications are closed.

## Mobile derivative

Direct 30k collapse was visually rejected despite a successful export and high bake hit count: the source's split/fragmented topology tore. The accepted ordinary-building trial instead welds the derivative, reconstructs a 0.003-unit voxel surface from the normalized neural source, reduces that source-derived surface to about 30k triangles, creates fresh UVs, and transfers original PBR data. Large parcels initially target 45k triangles. This is a starting specification, not an automatic quality guarantee: thin windows or recorded wall repairs may need a different source-derived processing method. Original raw geometry remains immutable. Bounded local patches may interpolate measured existing wall or mechanical boundaries and their UVs; they are separately recorded, never represented as additional neural inference or an authored replacement building.

Near textures normally use 1024 color and normal plus 512 roughness/metallic packing. A normal texture is omitted when actual diagnostic renders show its rebake damages the result; geometric normals remain. Attribute quantization preserves position/index/embedded-image bytes. A source-derived surface reconstruction is a lossy optimization, so logs and file-size checks never substitute for rendered inspection. The first approved shop is 29,997 triangles and 1,325,100 bytes. Original source defects, missing walls or excessive silhouette loss remain rejection reasons. Individual justified near exceptions up to 65k require explicit approval; they do not silently raise the whole-city default.

Current isolated experiments compare cleaned topology-preserving reduction, finer voxel reconstruction and closest-original-triangle texture transfer. These are not production-approved merely because export succeeds. The closest-surface path computes float64 barycentric UVs, records exceptional/degenerate interpolation and point reconstruction errors, and reports nearest-surface distance quantiles plus the fraction beyond 2% of the normalized maximum edge. Nearest lookup always finding a triangle is explicitly not a ray hit-coverage score or proof of preserved geometry. Every experiment still requires the five actual rendered sides and original-material comparison.

An initial same-run native-export diagnostic tested one additional mobile export. The local `native_mobile_export.py` adapter captures the actual decoded vertices, faces, neural attribute volume and coordinates on CPU, plus the native layout/grid/bounds parameters. The unchanged original 1M-target/4096 GLB export finishes first. Under the same GPU lock and same completed `run_mv` identity, the unchanged native Windows `to_glb` then performs a second 45k/1024 export using its CuMesh cleanup, simplification, UV unwrap and direct neural-field material sampling. This adds no neural generation, changes no shared code, does not replace the original raw and cannot approve itself. Its tensor archive, actual exporter/adapter evidence, timings, parameters and exact output hashes live under `native-mobile/{attempt}`. An optional derivative failure preserves a successful raw result. `process_native_mobile.py` only normalizes, JPEG-encodes, quantizes and renders that second output; it does not voxelize or rebake the facade again. Those direct native-simplification outputs were isolated diagnostics and were not accepted; the verified hybrid surface route below replaced that approach.

The first same-run mobile export added 20.33 seconds and froze a 443,921,885-byte tensor archive. Its facade material quality improved, but 30k/45k native simplification introduced lower-edge and back-eave defects, so neither variant was approved automatically. Later jobs now default to field capture only, with an explicit 12 GiB disk reserve and per-job actual archive size/free-space records. Existing older raw outputs are not regenerated just to obtain fields. Before the next job loads model weights, its GPU-lock holder now serves at most three independent short export requests with a 90-second soft batch limit, then starts the next neural inference. Classic requests have priority so its complete map can be reviewed first; this does not change raw-generation order or sampling settings. Every replay retains an independent receipt, and the inference report records the actual batch receipt list and elapsed time. Each receipt keeps the original field/inference identity separate from the job holding the lock; this is not another neural run. A local final-hole-perimeter experiment changes only the post-simplification native cleanup call in a separately snapshotted exporter, counts added faces, and requires checking that intentional openings remain open. Shared exporter files and approved candidates remain immutable.

The first visually accepted hybrid is Classic `card_pavilion`, SHA `a0b7f4b89e43ea28fcdea5ff9e312bebd1f31fdedc1d2a8d593946e11183598e`: 29,982 triangles and 1,148,764 bytes. It keeps the already complete CPU voxel-derived low surface, reverses its measured normalization into the same original neural-field coordinates, welds only identical positions, and lets native CuMesh generate UV charts and sample the original neural PBR field through the original high-surface BVH. The local exporter variant explicitly bypasses all further simplification, remeshing and cleanup. This avoids the native low-face simplifier's new eave holes while also avoiding the old Blender atlas/ray-transfer color triangles. The measured inverse-fit error is 1.155e-7; field-to-high-surface distance q95 is .001609 and q99 .002286, with no sample beyond .02. These are correspondence distances, not ray hit coverage. The actual five views and source comparison still determine acceptance.

`prepare_native_surface.py` freezes the exact low geometry and its processing report; `replay_native_mobile.py` copies all small proof JSON and actual executed tool sources into the trackable replay directory. Large tensor, intermediate GLB and NPZ archives remain local. `process_native_mobile.py` then only normalizes, encodes images, quantizes attributes and renders. `run_hybrid_queue.py` resumes these stages without approving outputs, skips already approved or animated assets and separately repaired surfaces, and records source-specific repair holds. Each candidate is keyed to the exact raw SHA and its original low-mesh SHA. The second independently reviewed large-building trial, Classic `onsen_2`, passed at 44,988 triangles / 1,676,396 bytes, SHA `d998685bd792f425e2c5a77990314474bde889c33c32cf6e34752976d829c265`. Captured-field candidates now use this continuing route, with independent per-asset visual review still required.

An explicit, isolated `process_lod.py --geometry-only` near intermediate can skip the temporary Blender UV atlas, texture transfer and low-stage renders when an exact original neural field exists. Defaults, components, far and legacy jobs remain unchanged. The intermediate records `geometryReady: true`, `processingComplete: false`, and exact float32 oriented-triangle preservation across GLB export; this proves the export preserved the chosen low mesh, not that reduction preserved the source visually. An actual triangle count above the existing near ceiling is held before field sampling. Native UV/field finalization still runs unchanged and renders five original-source and five final views; source-review reuse is prohibited for this mode. No intermediate can be visually promoted. Initial isolated trials completed the exact geometry/native-field checks and full visual reviews; their asset-specific visual failures remain rejected. The formal future-job sample, Harbor shop_1, passed exact low-geometry/native-field preservation, actual reference/source-five/final-five/256px review and approval portability; its frozen before/after evidence is under reports/geometry-only-opt-in-20261024/harbor-shop1-future/first-final-validation. Exactly eighteen untouched future ordinary jobs were then explicitly selected in remaining18-future-ordinary.json in the same opt-in report directory. Defaults, active jobs, budgets, memory guards and non-ordinary routes remain unchanged. Each final still requires independent visual review; this is not a default switch.

Recorded source repairs can enter the same material route only through the explicit `--allow-recorded-local-repair` preparation option. The normalization fit uses the actual repaired source, while the original raw and field identity remain separate and unchanged. Proofs include the repaired-source hash, repair receipt, executed repair-tool snapshot and exact low-mesh lineage. A replay's no-new-geometry statement applies only to native UV/material replay, never to the earlier disclosed repair.

For older sources without a captured field, the closest-original-triangle path remains available. A controlled same-geometry UV experiment on the locally repaired Classic villa level 3 showed that 89-degree Smart Project islands internally overlap: changing only the projection angle to 66 degrees reduced different-surface pixel collisions from 3,378 to 455 and removed visible shutter triangles, with every exported triangle-corner position unchanged. Increasing margin alone reduced usable atlas coverage too far. This finding does not automatically approve other meshes or justify changing already approved derivatives.

The older Harbor villa level 2 exposed a separate subpixel-chart problem: 17 sampled visible blue-roof faces became cream-colored in the exported atlas even though their nearest original source colors were all blue. Native CuMesh UV-only unwrapping on its exact 44,985-triangle surface took 2.69 seconds under the shared GPU lock, with no remesh, simplification, face addition, position or winding change. CPU float64 original-image transfer onto those charts reduced the measured cream-colored roof samples from 17 to zero. Its five sides and 256-pixel phone-scale views were independently reviewed and the resulting 1,709,688-byte candidate, SHA `9edbb3489ce0c5aed37e0d27901191e860f3cc88dc5553848abc599e42d351b7`, was approved. `native_uv_unwrap.py` records exact oriented triangle signatures and snapshots; `bake_native_uv_candidate.py` assigns returned UVs back to the saved original low-mesh loops and verifies unchanged triangle positions, index order and corner normals. This route retains the older original texture source and does not claim a captured neural field or additional inference.

Each actual exported GLB is reimported and rendered with Cycles CPU, four threads, 512-pixel views and 16 samples: front, right, back, left and iso. Original raw front and iso use the same normalization and camera framing. A review sheet composes these unchanged render images with labels. Candidate reports remain `exported_pending_visual_review`; only the root review registry approves exact hashes. Processing reports record raw/inference/reference/tool hashes, actual triangle count, texture sizes, Y-up bounds, limitations and output SHA.

## Resume and revision behavior

`run_raw_queue.py --watch` serializes GPU jobs with immutable attempt names. It adopts only completed, hash-verified native reports. A new canonical triptych or an existing attempt prevents fallback adoption of an older house source. An updated reviewed reference invalidates the old current source while preserving previous revisions and attempts. A requested source retry changes the explicit seed and output identity, without overwriting old raw evidence. `run_lod_queue.py --watch` keys work to each raw SHA and processing revision, serializes CPU work, produces review sheets and does not treat Blender's exit code alone as success. Explicit repaired-source and repair-report inputs remain distinct from `source.rawGLB`; the original inference hash does not change. Failed jobs remain inspectable rather than becoming approval.

The CPU lease additionally orders live eligible waiters by their original enqueue time. A long-waiting gray review therefore takes its turn before a newly queued reconstruction when both satisfy their own RAM guards. A memory-ineligible 9 GiB waiter still does not block an eligible 4.5 GiB task. Real two-process Windows-lock checks exercise both cases with synthetic memory, separately from production; the frozen test receipt is `reports/throughput/cpu-lease-fairness-validation.json`. Controllers load this change only after their current child naturally completes.

Exceptional near reconstruction at voxel size <=0.0015 now also takes the existing operating-system GPU reservation for its CPU process lifetime, before any high-resolution mesh import. This reserves memory residency, not GPU compute; Cycles stays on CPU. Native loading uses that same lock and checks for fine-voxel Blender processes started before the guard rollout. A busy reservation is recorded as `gpu_busy` / `resource_wait` with `generation_started=false`, so the raw queue schedules a retry without charging an inference failure. Ordinary .002/.003 CPU processing, far surfaces and small reviews do not request this additional reservation. No memory threshold or model setting is reduced. Already-running jobs finish normally. Legacy already-waiting parent controllers receive the guard when they launch their next Blender; such a fine job can temporarily wait behind a native run while holding its CPU lease, but cannot overlap model residency. Actual Windows lock tests in `tools/check_native_memory_reservation.py` cover both exclusion directions, ordinary CPU bypass and resource-wait classification without loading any model.

Formal asset packing and publication belong to the root integration task. This pipeline writes only source, candidates, reports, diagnostics and input preparation outputs. Mechanical animation candidates require separately inspected real neural parts; static exports are not evidence that the animation requirement is complete.

A reviewed cleanup of the same raw source increments its processing revision. The hybrid controller only accepts a low candidate with that current revision, uses a distinct replay identity for each nonzero revision, and preserves superseded replay requests/results. An already-running native export may finish, but its old surface is not promoted over the new revision. This avoids confusing a ground-cleaned derivative with an earlier same-source surface.

Promotion also rereads exact-raw visual holds immediately before changing the candidate inbox. A rejection received while CPU admission or rendering was in progress preserves the completed isolated comparison but cannot replace the current candidate. Explicit recorded repair inputs use their separate lineage and remain eligible. `check_promotion_hold.py` exercises this late-hold race in a temporary directory, including proof that the prior candidate and its history were untouched.

In watch mode the source controller remains available after all 147 raw sources exist. Late CPU derivatives can still enqueue native UV/field exports, which `run_export_tail.py` serves under the same GPU lock and startup guards in short batches. It imports the verified export environment but loads no neural model weights and performs no new inference. Each tail invocation has a separate receipt and the ordinary per-export provenance; later explicitly requested source revisions also remain discoverable. Completing the raw stage is never treated as finishing visual approval or release.

An explicit RAM/physical-VRAM startup-guard refusal is counted as a scheduling wait only when its immutable report says `generation_started: false`. It does not spend the per-reference neural-failure retry budget. Unknown exceptions, missing generation flags and failures after inference starts remain real failures requiring their ordinary review. Queue state links the original guard receipt without changing that receipt; `check_raw_resource_wait.py` checks both the positive guard cases and these rejection cases. The existing admission thresholds remain unchanged.

The parent source scheduler also checks for a live fine-voxel worker before launching another inference attempt or export-tail process. A known fine worker creates a scheduler `resourceWait` record and a ten-second wait, not dozens of known-busy inference attempts. This read-only advisory gate does not replace the actual shared OS byte lock or change the lock order. Earlier immutable `generation_started: false` wait receipts remain preserved.

One isolated single-front comparison uses the exact Alpine tower level 1 a003 front pixels, seed23421,1024 shape and4096 raw texture. Its manifest and measured stages live under `experiments/alpine-tower1-a003-single-front-23421`; it is excluded from the147 formal multiview identities and every approval/release path. The single and multiview checkpoints and official internal preprocessing differ, so equal integer seeds are not equal random processes. The measured single run took328.81s versus246.66s for the preserved multiview baseline, with different generated sparse-token counts and system load. That one timing result does not establish a route-wide quality or speed advantage; actual four-side and equal mobile-budget review remain separate requirements.

CPU-lease advisory JSON replacement and waiter deletion tolerate short Windows sharing conflicts with bounded retries on the same path and FIFO timestamp. A permanent failure is not disguised as admission; the actual OS lock is released and its handle closed even if metadata cleanup fails. Tests hold real Windows read handles without delete sharing, then verify successful retry, bounded permanent-denial handling, eligible-waiter FIFO and safe bypass of RAM-ineligible waiters. No resource threshold is lowered.

## Far surfaces and mechanical derivatives

After Classic's complete near/far set passed individual review, source scheduling retains reviewed reference/source revisions first, then prioritizes Alpine's ungenerated public and large buildings before new ordinary cores in later maps. This lets the public and core reviewers work in parallel and prepares a second complete map for scene review. All 147 source identities and quality parameters are unchanged; `check_raw_queue_priority.py` verifies preservation and ordering. The current neural attempt always finishes before a scheduling update is loaded.

The first 6k far trials were rejected: direct raw reduction folded walls, and a second-generation tangent normal bake caused black dormers and chimneys. The approved engineering budget is now 12k triangles, 512 color and 256 ORM, using geometric normals. Far geometry starts from the exact approved near GLB, welds duplicate positions, then runs PyMeshLab quadric collapse with topology, normal and boundary preservation and planar quadrics. `derivedFromNear` records the approved source path/hash; the original native inference and raw hashes remain in the report. Each far export still requires external visual approval. The local optional CPU dependency is PyMeshLab 2025.7.post1, isolated in `runtime/packages`; no shared Pixal environment files or model weights are changed.

Classic villa level 3's 12k native-UV variant removed the earlier white atlas triangles but still damaged dormers and cornices. It remains rejected. The initial isolated 20k preparation was not published; the measured street layout contains eight villa level 3 copies and four shop level 2 copies, so the active trial is 18k from the same approved near surface (about 192k total street triangles). A 19k variant would require demonstrated need and individual review; 20k is not accepted for that unchanged 200k layout budget. This is a single-asset exception, not a raised global default. Already approved far bytes are skipped regardless of later controller defaults.

Classic tower level 2 separately required an approved 18k far exception after its 12k topology-preserving reduction damaged dome and window edges. The accepted 18k mesh retains the exact reviewed near source and native-UV 512/256 transfer. It has no instance in the current Classic outer street layout, so that layout remains about 192k triangles. The global far default and total street budget are unchanged.

When an apparent source defect may have arisen during the original 1M-target export, `diagnose_decoder_roi.py` memory-maps the preserved pre-export decoder tensor on CPU and selects whole original faces inside an explicitly documented diagnostic region. It retains original vertex/face IDs and applies the same measured normalization as the 1M GLB. `render_decoder_roi.py` uses identical neutral material, camera and lighting for both stages, without remeshing or repair. Deliberate ROI crop boundaries are not reported as source holes. This diagnostic cannot approve a mesh or automatically trigger another inference.

An explicitly reviewed local color defect can be corrected after native field replay by assigning a bounded set of UV corners to intact same-building donor triangles. The Rush station proof preserves the pre-correction candidate and processing report, actual tool, target/donor IDs, final model and five rendered views. Its independent check requires every triangle-corner position and normal, every material, and every embedded image byte to remain unchanged. `postNativeUVCorrection` exposes this as an additional processing stage; it is never claimed to be unchanged direct neural-field output.

`neural_component.py` partitions only existing derivative triangles and preserves embedded image bytes. Public wheels and suspended cargo use independent nodes with `extras.lifePart`, with local Z aligned to the actual axle or swing plane. They contain no autoplay GLTF clips, since runtime scene-life supplies the movement. Pose-zero geometry error, triangle totals, image hashes, component selection and actual moved-frame renders are recorded. Heroes use a separately reviewed GLTF-clip contract. No whole-building motion substitutes for a mechanical component.

Hero pendulum clips are inspected at neutral time and at one-quarter and three-quarter of the cycle, where the recorded swing keys reach opposite extrema. Signed swing angles are not treated as spin timestamps. The harbor lighthouse keeps its original static waterwheel and animates only the original hanging lantern; its separately disclosed small connector repair stays stationary.

Mechanical clipping can increase triangle count before the explicitly disclosed boundary closure. Native-transfer validation binds the pre-motion surface and frozen repair, verifies the exact clipping increment per original face, and reads both actual GLBs to check retained triangles, clipped-piece positions and areas, cap areas and interpolated donor UVs, static/moving counts, materials and embedded image bytes. It does not accept a count inequality as evidence. The Compact wheel proof accounts for 1,274 clipping triangles plus 426 local closure triangles; 37 destructive proof/binary tests cover the branch, including mismatched portable-copy hashes and sizes.

Localized repairs preserve original vertices and the untouched raw source. Small added boundary surfaces require source-bound region, original-UV and added-triangle evidence. Removing an inward fold additionally requires exact removed source IDs, measured region and depth limits, an independent surviving POSITION/UV triangle-multiset check, and unchanged embedded images. The two small Alpine workshop roof regions use a measured-plane/depth branch. Expansion wheel v2 has a separate exact-source exception for 2,527 extraneous backing faces outside its measured wheel circle and 250 inward lintel faces; all 952,909 surviving source faces retain exact positions and UVs. Its validator checks both bounded regions and counts, rejects disc deletion, and has 23 invalid-proof tests. These exceptions do not authorize whole-building replacement or unrecorded geometry changes.

A later Alpine workshop low derivative had one measured long, isolated triangle outside the repaired source bounds. `clean_derivative_spike.py` removed only that triangle and its unreferenced outlier vertex. Its receipt records the exact input/output, deleted index, source-bound tests and unchanged retained triangle positions, UVs, normals and embedded images. This is a separate derivative cleanup after the recorded source repair; the raw and repaired source bytes remain untouched. Native UV transfer follows from the cleaned low mesh, with fresh static and motion review still required.

## Uniform family placement and release binding

The packer fits every intact approved source uniformly inside its existing parcel. For a complete three-level family, it then works downward from level 3, limiting each lower level to 86% of the next level’s actual height only when needed. No source vertex or UV is rewritten and no parcel is expanded. The manifest records the independent fit, applied scale and reason; a large reduction is a prompt for actual shared-camera inspection, never automatic visual approval. Far copies are bounded by the exact approved near source’s packaged height.

Regional visual approval binds the exact near, far and applicable landmark package hashes as well as individual model hashes and screenshot bytes. Publication rechecks those package identities after rebuilding and before replacing any runtime file, so a later scale or placement change cannot reuse an older scene review.

Evidence under `art/` and model assets under `assets/models/` use Git `-text` attributes. Some original Windows receipts and tool snapshots contain CRLF, so forcing LF would invalidate their SHA-256 after checkout. `check-provenance-git-bytes.mjs` compares Git's filtered and unfiltered hashes on actual frozen evidence and checks future far/hero manifest coverage. Do not normalize an already frozen file's line endings.

Approval validation explicitly passes the exact approved final-copy receipt into mechanical binary checks. Frozen processing reports may retain historical scratch paths, but copied final bytes must match both their SHA and size before validation. `check-approval-portability.mjs` simulates a checkout with every Git-ignored scratch/archive file absent; approved assets must still validate from committed evidence. Raw source archives remain optional for the normal release check and mandatory only for the separately requested archive audit.

UI building previews are copied byte-for-byte from each approved model's actual iso render, including all 21 upgrade models and eight public buildings per map. `pack_runtime.py` creates `packed/previews/<region>` for candidate review and publishes `assets/buildings/regions/<region>` with the complete release. Each preview manifest binds the exact approved model and render hashes. No independent illustration or legacy regional substitute represents the new model. Images load lazily, and the three Classic landmark parcels now carry explicit family keys, matching the 3D resolver. `check-building-previews.mjs` checks all 29 routes and image identities per completed map.

Before the full release, enable the live preview helper in `game.js` by removing its temporary candidate-only return, remove the old SVG/legacy building-thumbnail branches, and switch `regionalSceneryDirectory` to `regions-far` for both normal and candidate play. Then run preview checks for all five published maps and the full release audit. These temporary switches keep the currently incomplete asset set out of the normal game.
